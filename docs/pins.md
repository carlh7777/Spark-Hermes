# Pins

What every round is measured against. A change to any row changes what miners are scored on, so it is a
deliberate, dated act — and a new era when it changes the reference arms' comparability.

## Round clock (2026-09-16)

| Parameter | Pin | Where |
|---|---|---|
| submission window | **120 min** from open; the seal is taken at close, by PR head SHA. A window that closes with no valid submission (an incumbent alone does not count) **reopens**: same round, same tasks, a fresh 120 min, recorded in `window.json` (`reopened`, `reason`) — nothing is sealed, evaluated or revealed. `submissions/` carries exactly the current king: a dethroned incumbent is removed at announce | `sh/validator/orchestrate.py --window-minutes` |
| tasks per round | **6** (one RTX 5090 evaluates ~18 episodes an hour; a round with fewer than 4 is re-minted), minted ahead by `supply.queue` (`--ahead 3`); future rounds published only as digests in `rounds/queue.json`, over the tasks and their previews. For a previewing family (`swe_fix`) miners get the previews at open and the evaluated tasks at close | private repo |
| attestation | `sh-attestation-v2`: `sr25519(hotkey, "spark-hermes:<repo>:<round>:<bundle_sha256>:<signed_at>")` in `attestation.json`. One submission per hotkey per round: the **latest signed** counts (not the newest PR — signed bundles are public and could be reopened by anyone); a signing time more than 10 min in the future is refused. | `sh/cli/attest.py`, `orchestrate.one_per_hotkey` |
| PR scope | a strategy PR changes exactly one `submissions/<hotkey>/` and **nothing else** (never `sh/`, config, another hotkey); its directory name must be a valid ss58. The crown is merged **only at the sealed head** (`--match-head-commit`), so a push after the seal cannot slip unevaluated code into `main` | `orchestrate.candidates`, `announce` |
| S1 — copied answers | a challenger sharing more than 8 distinct solution lines (≥ 24 chars) or more than 40 distinct 12-token runs with the round's private reference/alternate solutions and verifiers (for `swe_fix`: the code its bugs replaced) — text that also appears in a task's prompt, or in a preview's, excluded — is refused at seal. | `sh/validator/similarity.py` |
| crown | best Δ credit vs baseline on **this round's** instances, > 0, ≥ 4 paired, **not disqualified this round**; among the eligible a tie **does not dethrone** the incumbent; other ties by pooled Δc then a round-keyed hash (not the hotkey name). A round where nobody beats the baseline crowns nobody | `sh/scoring/crown.py` |
| dethrone | the incumbent leaves `submissions/` at announce only when **(a)** a challenger is crowned over it, **(b)** its pooled 8-round window fails the correctness gate on enough evidence (`mean_d + z·se < 0`, the evidence payment uses), or **(c)** it has gone **3 rounds in a row** without the crown. A single round that crowns nobody does **not** dethrone (on 6 instances a better strategy ties the baseline by noise about a third of the time) | `orchestrate.dethroned` |
| engine budget | one RTX 5090 serves two long agent contexts. A call the engine refuses for capacity is **held by the proxy and retried** (up to 240 s) instead of failing — a refusal would otherwise void the whole episode. The **reference strategy** (canon) runs only in calibration rounds, every 8th (`--canon-every`); it labels families and is never paid, and the pooled window carries its measurements between calibrations | `sh/validator/proxy.py`, `orchestrate.evaluate` |
| reward | the crowned pull request, merged at the sealed head, is what the reward follows (Gittensor workflow). The crown is decided on **this round's instances alone**: best mean Δ vs baseline > 0, ≥ 4 paired, not disqualified. `score`/`Δc`/`weight` are published diagnostics over the pooled window, not the reward, and read 0.000 at current sample sizes | `sh/scoring/crown.py`, `orchestrate.announce` |
| pooled statistic | pooled over the last 8 rounds. **score** = the paired mean Δ of credit vs the baseline over the window, after the overfit and copy penalties (signed); **weight** = a score's share among the strategies above the baseline, summing to 1; **Δc** = the one-sided 90 % lower bound of that mean, published beside them as how sure the gain is. The efficiency term is off (w_e = 0): it penalised honest correctness gains and paid worse-than-baseline strategies for fewer calls. The reference variance is floored (max-entropy over n) so a degenerate all-identical null arm cannot make the baseline look certain | `sh/scoring/v2.py`, `--window-from` |
| training data | SFT: the king's episodes where **every** check holds; DPO: the king's episode with credit ≥ 0.8 vs another surface's with at least 0.5 less, same instance; no king → nothing uploaded | `sh/exports/build.py` |

## Family #4 — `swe_fix` (2026-09-17)

| Component | Pin | Where |
|---|---|---|
| seed material | SWE-smith (`SWE-bench/SWE-smith`, MIT): bugs injected into real Python repositories, each with an issue-style problem statement, the bug's diff, the tests it breaks (FAIL_TO_PASS) and the tests it leaves passing (PASS_TO_PASS), on a per-repository environment image. Indexed: 23,129 usable of 59,136 rows (the dataset as of 2026-09-17; `docs/seed-datasets.md` cites the paper's 50,137) (a problem statement, 1–10 broken tests, ≥ 5 passing, a diff that touches no test infrastructure). Rounds draw from 12 pure-Python repositories. Each bug is used at most once | private `supply/swesmith.py`, `supply/families/swe_fix/repos.json` |
| pilot | 20 bugs over 5 repositories, pinned model with no strategy, alone on the GPU: 17 valid, mean credit **0.34**, 4 fully resolved, 4 partly, 9 not at all; no kept test broken; **9 of 17 used all 30 turns** (the harness cut in — `1 - success` on that pilot mixed "could not" with "ran out", unseparated at the time) | 2026-09-17 |
| task images | `swe-task:<opaque key>` = the environment image at the bug's branch with its **git history cut to one commit** and no bytecode compiled before the bug (a pilot agent read the injected diff out of `git log`), plus the Hermes layers of `hermes-ubuntu:pin`. Built once, on the worker; `images/<key>/SOURCE.json` names the dataset, license, repository and environment — never the bug | private `supply/swesmith.py` |
| previews | miners are shown **different bugs from the ones scored**: each evaluated bug has a preview — another bug from the same repository and environment, with its SWE-smith instance id so it can be reproduced locally — and only previews are in `rounds/<id>/tasks/` while the window is open. A strategy is paid for debugging these codebases, not for knowing eight one-line answers. The evaluated tasks are published at close in `rounds/<id>/evaluated/`, and `reveal.json` names each one's SWE-smith instance id — the committed test ids are that bug's own tests, readable in the dataset; `rounds/queue.json` commits to both before the round opens | `supply/families/swe_fix/family.py`, `orchestrate.shown` |
| universe | one `custom swe_test <node id>` per broken test, **all withheld** (split `withheld`: nothing published, so no overfit rule applies and a partial fix is partial credit). The grader receives the broken tests' files (as they were before SWE-smith deleted those tests) and the kept tests in `withheld.json.assets`, never the agent | `supply/families/swe_fix/checks.py` |
| grading | in a fresh read-only container over the agent's final tree: bytecode deleted; test infrastructure the task did not ship (a new `conftest.py`, `sitecustomize.py`, `.pth`, `pytest.ini`, anything under `tests/`) removed; the broken tests written back; one `pytest --verbose` run parsed the way SWE-smith parses it. A broken test counts only if it passes **and no kept test fails**. Shipped test infrastructure is a protected path: modifying it disqualifies | `checks.py`, `sh/validator/grade.py` |
| kept tests | up to 60 passing tests from the broken tests' files and 40 from elsewhere, sampled per bug; at mint, only those that pass both on the bug and after the reference are kept | `swesmith.sample_p2p`, `family.kept_tests` |
| derivation | every broken test fails on the untouched tree and passes after the reference (the bug's diff reversed), twice; the gate re-proves it | private `supply/derive.py`, `supply/gate.py` |
| admission | one baseline episode per sealed task; admitted when the pinned model with no strategy does **not fully** fix it (credit < 1). A baseline 0 is admitted: unlike FACET, a real bug with its failing tests is fixable, and 0 is where strategies have the most room | `ops/start-queue.sh --screen-band 0.0:0.99` |
| S1 | compared with the code the bug replaced (the diff's removed lines), not with the diff's context or the repository's tests, which quote the repository miners can read | `sh/validator/similarity.py` |
| limits | a **token budget of 600k** (prompt + completion − reasoning tokens, as the engine counts them; enforced by the proxy, which answers `402` and marks the episode — `token_budget_spent`, graded normally, never void) is the binding limit from r0005: what an episode costs does not depend on what else runs, and a lean context buys more turns. Reasoning tokens, when the engine reports them, draw on a separate allowance of **2× the token budget** — the same argument the runner makes for thinking-only turns, so deliberation does not steal the action budget. Backstops: `max_turns` 100 plus `max_reasoning_steps` defaulting to 2× that (a reasoning-only API call no longer spends an action), `timeout_s` 1800 (r0004 ran 30 turns / 600 s: 3 of 16 capped episodes were cut off by the clock while a third of that clock went to queueing). `truncated_episodes` / `truncated_failures` sit on the suite record beside the rate. Tools `terminal` + `file`, network none; suite timeout 480 s | `family.py`, `sh/validator/proxy.py`, `sh/validator/truncation.py` |
